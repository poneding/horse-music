# 一头诗人 · 功能缺口与开发进度

> 这份清单从播放器实际使用路径出发，按「影响日常听歌的程度 ÷ 实现成本」排序。
> 本轮目标：补齐播放核心闭环，并完成一批低风险、高感知的曲库与部署能力。
> 多用户、离线音频、转码等需要改动数据模型或引入新基础设施的功能单独列为后续阶段。
>
> **本轮状态：P0 / P1 / P2 已完成，P3 保持后续规划。** 具体验证结果见文末「本轮验收」。

## 优先级说明

- **P0**：播放器主路径上的功能空洞，必须补。
- **P1**：明显影响日常使用或数据可靠性，成本可控。
- **P2**：锦上添花，本阶段尽量完成。
- **P3**：需要架构调整，本阶段只记录方案，不实施。

## 验收方式

- `make check` 通过（Node 与服务端语法、前端 ES module 语法）。
- 启动本地服务，用真实曲库做冒烟：播放、暂停、切歌、队列增删排序、刷新恢复、收藏持久化、排序与筛选、搜索分组、管理端批量删除。
- 媒体会话在支持 `navigator.mediaSession` 的浏览器中验证元数据与动作。
- 数据文件兼容旧格式：缺少 `favorites.json` 时自动创建；旧 `library.json` / `plays.json` 不受影响。

## 本轮实现摘要

- **播放会话**：`localStorage['horse-playback-v1']` 保存音量、静音、队列、当前曲目、进度、随机与循环模式；刷新后恢复为暂停状态，并保留播放位置。
- **队列**：队列条目带稳定 key，允许同一首歌重复入队；支持下一首播放、加入队列、移除、拖动排序、清空；队列弹窗监听 `horse:queuechange` 实时刷新。
- **随机播放**：独立的未播放池与历史栈；随机池为空时按循环模式重新洗牌或停止；上一首按历史回退。
- **系统媒体控制**：`src/features/media-session.js` 提供标题、歌手、专辑、封面和播放/暂停/上一首/下一首/进度动作。
- **快捷键**：空格、`←`/`→`（Shift 为 30 秒）、`M`、`L`、`S`、`R`；播放条增加静音按钮。
- **收藏**：`favorites.json` 服务端存储，`/api/state` 下发；首次升级合并 `luma-favorites`；同一首歌的并发收藏请求用序列号防止旧响应覆盖新状态；删除歌曲时同步清理收藏。
- **排序与搜索**：最近添加/歌名/歌手/时长/播放次数排序；风格从曲库派生；专辑/歌手/歌单分组；最近搜索下拉（浏览器本地）。
- **PWA**：manifest、192/512/maskable 图标、Service Worker 预缓存外壳与全部 `src/**` 模块；`/api/`、`/media/`、Range 请求明确不缓存。
- **管理端**：歌曲多选、批量删除（最多 500 首）、批量加入歌单、存储占用统计。
